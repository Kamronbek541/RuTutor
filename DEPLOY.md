# Деплой RuTutor на Railway

## Главное: база должна лежать на Volume

Бот хранит всё в одном файле SQLite: ученики, XP, классы, прогресс по урокам
и кеш сгенерированных уроков. Файловая система контейнера Railway **временная** —
она пересоздаётся при каждом деплое. Без подключённого Volume все данные
пропадают при каждом обновлении кода.

### Как подключить Volume (один раз, 1 минута)

1. Railway → проект → сервис с ботом.
2. Вкладка **Variables / Settings** → **Volumes** → **+ New Volume**.
3. Mount path: **`/data`**
4. Deploy.

Больше ничего делать не нужно: бот сам находит подключённый диск
(через `RAILWAY_VOLUME_MOUNT_PATH` или каталог `/data`) и кладёт базу в
`<том>/rututor/bot.db`.

### Как проверить, что всё правильно

Напишите боту **`/dbstatus`**. Должно быть:

```
✅ постоянное хранилище — деплой данные не сотрёт
Путь: /data/rututor/bot.db
```

Если написано «⛔️ ВРЕМЕННЫЙ диск» — Volume не подключён, данные снова пропадут
при следующем деплое. То же предупреждение бот печатает **в логи** при старте.

Никаких рассылок в Telegram бот при этом не делает: это техническое сообщение
для владельца, а не для учеников. Если уведомление всё-таки нужно — задайте
`RUTUTOR_ALERT_CHAT_ID` со своим Telegram ID (узнать его: команда `/myid`),
тогда предупреждение придёт в этот один чат не чаще раза в 12 часов.

### Уборка технических сообщений

Если бот успел разослать администраторам служебные предупреждения, команда
**`/cleanup_alerts`** (только админ) найдёт и удалит их в чатах всех
администраторов. Она пересылает каждое сообщение себе, чтобы прочитать текст,
и удаляет только те, что совпали с шаблоном — чужие сообщения не трогает.

Telegram разрешает боту удалять сообщения не старше **48 часов**; всё, что
старше, останется в чате.

### Резервная копия

Команда **`/dbbackup`** (только админ) присылает файл базы прямо в чат.
Полезно сделать перед любым рискованным изменением.

Чтобы восстановить базу из такого файла: положите его на сервер (или в том)
и укажите путь в переменной `RUTUTOR_LEGACY_DB_PATH` — при старте бот
перенесёт данные в рабочую базу, если она ещё пустая.

## Переменные окружения

| Переменная | Обязательна | Назначение |
|---|---|---|
| `BOT_TOKEN` | да | Токен бота от @BotFather |
| `OPENAI_API_KEY` | да | Ключ OpenAI для проверки письменных работ |
| `OPENAI_MODEL` | да | Модель OpenAI |
| `ADMIN_IDS` | желательно | Telegram ID администраторов через запятую |
| `RUTUTOR_DATA_DIR` | нет | Каталог для базы вручную (если Volume смонтирован не в `/data`) |
| `RUTUTOR_DB_PATH` | нет | Полный путь к файлу базы вручную |
| `RUTUTOR_LEGACY_DB_PATH` | нет | Путь к старой базе для разового переноса |
| `RUTUTOR_ALERT_CHAT_ID` | нет | Куда слать техническое предупреждение о временном диске (один чат) |

### Про ADMIN_IDS — важно

Если `ADMIN_IDS` **не задана**, бот использует список по умолчанию, зашитый
в коде. Эти люди получают доступ к админ-панели и уведомления о жалобах
на вопросы. Проверить действующий список: `/dbstatus` — он показан внизу.

Чтобы задать свой: узнайте ID командой `/myid` и впишите его (или несколько
через запятую) в переменную `ADMIN_IDS` в Railway.

## Команда запуска

`python bot.py` — задана в `railway.json` и `Procfile`. Бот работает через
long polling, веб-порт не нужен, поэтому тип сервиса — **worker**.

⚠️ Нельзя запускать два экземпляра бота с одним `BOT_TOKEN` одновременно
(например, локально и на Railway) — Telegram отдаёт обновления только одному,
второй будет падать с ошибкой конфликта.

## После первого деплоя с пустой базой

1. Создайте класс: `/admin` → **🏫 Классы** → создать, получите код.
2. Раздайте код ученикам: они пишут `/join КОД`.
3. Учитель подключается: `/teach КОД`, дальше пользуется `/teacher`.
4. Прогрейте кеш уроков: `/prewarm` (уроки 1–5 и 7–9 первого и второго
   семестров написаны вручную и в прогреве не нуждаются).
