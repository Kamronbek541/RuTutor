# Отчет по доработкам RuTutor

Дата: 2026-09-23
Основание: замечания преподавателя от 21.09.2026.

## 1. XP теперь считается по урокам

**Было:** XP — одно кумулятивное число `users.xp`. Разбивки не существовало нигде.

**Стало:** появился журнал начислений `xp_ledger` — одна строка на каждое изменение XP
с указанием источника и ключа урока.

- Новая функция `storage.award_xp(user_id, delta, source, lesson_key, note)` —
  единственная точка изменения XP. Меняет `users.xp` и пишет строку журнала
  в одной транзакции. Возвращает **фактически применённую** дельту: `users.xp`
  клампится на нуле, и без этого сумма по урокам не сходилась бы с общим XP.
- `storage.add_xp()` оставлена тонкой обёрткой (`source='legacy'`), чтобы ничего
  не сломалось у стороннего кода.
- Все 13 мест начисления переведены на `award_xp` с ключом урока:
  КТП → `s1_01`, тренажёры → `mod:<модуль>:<уровень>`, уроки класса → `class:<дата>`,
  глобальное (стрик, входной тест) → пустой ключ.
- Бонус +25 за первую сдачу мини-контрольной пишется отдельной строкой журнала,
  чтобы отчёт совпадал с текстом правил.

**Инвариант:** `SUM(xp_ledger.delta) == users.xp` для каждого ученика. Проверяется тестами.

### Разовый пересчёт истории

`storage.backfill_xp_ledger_once()` восстанавливает историю для учеников, которые
занимались до появления журнала:

- по `ktp_lesson_progress`: `practice_best × 2`, `exam_best × 3` + 25 при сдаче;
- письменные работы **переигрываются** по реальным записям `writing_submissions`
  (там сохранены оценки ИИ), поэтому считаются точно;
- остаток `users.xp − сумма журнала` кладётся в корзину `__legacy__`
  («До обновления») — так сумма по урокам сходится с общим XP.

Идемпотентно: флаг в `app_meta` + `UNIQUE INDEX ... WHERE source='backfill'`
с `INSERT OR IGNORE`. Вызывается один раз из `bot.py` при старте; повторить
вручную — `/xp_backfill` (принудительно: `/xp_backfill force`).

### Экраны

- Ученик: **🎁 XP по урокам** — в профиле и в меню учебного плана.
- Учитель (`/teacher`, доступ по коду группы через `/teach`): класс → XP по урокам,
  XP по ученикам, разбивка конкретного ученика, выгрузка CSV.
- Админ (`/admin` → класс): то же самое плюс экспорт.
- CSV: `xp_total`, `xp_ledger_total`, колонка на каждый урок, `xp_legacy`, `xp_other`.

## 2. Понятные правила начисления XP

Новый модуль **`xp_rules.py`** — единый источник правды: все константы XP,
чистые функции расчёта и `render_xp_rules_text()`, который собирает русский текст
справки **из тех же констант**. Текст физически не может разойтись с кодом;
на это есть отдельный тест.

- Экран **ℹ️ Как начисляется XP** (`xp:rules`) — из помощи, профиля, экрана XP
  и панели учителя.
- Из текста помощи убраны продублированные правила, чтобы источник остался один.
- Пороги, ранги и пороги достижений тоже переехали в `xp_rules`.

## 3. Выключатель встроенного ИИ для класса

Новая таблица `group_settings(group_id, key, value)` и резолверы
`storage.is_ai_enabled_for()` / `are_hints_enabled_for()`.

- Правило: запрет строже разрешения — если ИИ выключен хотя бы в одном классе
  ученика, он выключен. Учителей ограничение не касается.
- Управление: `/teacher` → класс → «🤖 ИИ: выключить» / «💡 Подсказки: выключить».
  То же есть в `/admin`. Статус виден на экране класса.
- Применяется в шести местах: три входа в ИИ (письмо КТП, письменное задание
  тренажёров, домашнее задание класса) и три обработчика подсказок. Кнопка
  и прячется в клавиатуре, **и** проверяется в обработчике — на случай старого
  сообщения с уже нарисованной кнопкой. Текстовые обработчики режима письма
  тоже проверяют флаг.

**Важное ограничение, честно:** бот не может заблокировать внешний ChatGPT на
телефоне ученика. Выключатель отключает только ИИ внутри бота.

## 4. Ошибка в уроке 1, Практика 1, вопрос 11

Исходная причина: урока `s1_01` не было в коде — он генерировался ИИ и кешировался
в базе. Плюс вопросы перемешиваются на каждой попытке, поэтому «11-й вопрос»
у разных учеников — разные вопросы, и по номеру ошибку не найти.

Сделано:

1. **Проверенные пакеты для `s1_01` и `s1_02`** (уроки, которые класс проходит сейчас):
   теория, словарик, 12 вопросов практики, 8 вопросов мини-контрольной, письменное
   задание, рекомендации. Рукописный пакет имеет приоритет над кешем ИИ, поэтому
   старая версия перестанет показываться **без ручной чистки базы**.
2. **Исправлен корневой баг в `quiz_utils`**: дедупликация вариантов выполнялась
   до разрешения индекса `correct`, и индекс не пересчитывался — при совпадении
   двух вариантов (в том числе по ё-нормализации: «сёстры»/«сестры») ключ молча
   съезжал на соседний вариант. Добавлена карта «старый индекс → новый».
3. **Исправлены два живых вопроса** с повторяющимися вариантами, из-за которых
   ученик видел 3 варианта вместо 4: `content.py` `noun2_9` и `ai.py` `s2_08_q3`
   (там же была опечатка «сделанна»).
4. **Кнопка «⚠️ Ошибка в вопросе»** под каждым вопросом (КТП, тренажёры, контрольная,
   уроки класса). Сохраняет точный текст вопроса, варианты и ключ в таблицу
   `question_reports` и уведомляет админов. Экран `/admin` → «⚠️ Жалобы на вопросы»
   с кнопкой «Обработано». Дубликаты от одного ученика в течение часа не создаются.
5. **Тест целостности контента** по всем 514 встроенным вопросам: ровно 4 различных
   варианта (с учётом регистра и ё), `correct` в диапазоне, и ключ не меняется
   после нормализации. Плюс проверка комплектности рукописных пакетов (12/8).

## Проверки

```bash
python3 -m unittest discover -s tests   # 40 тестов, OK (было 13)
python3 -m compileall -q .              # OK
```

Дополнительно проверено на временной базе:

- `award_xp` с клампингом: у ученика 1 XP, списание 5 → `users.xp = 0`,
  в журнале `−1`, сумма журнала равна общему XP;
- пересчёт истории на сиде «777 XP + прогресс по урокам»: суммы сходятся в 777,
  повторный запуск ничего не меняет, `force` даёт тот же результат;
- `predefined_ktp_package("s1_01"/"s1_02")` → 12/8 вопросов, нормализация не меняет ключи;
- импорт `bot.py` с регистрацией всех обработчиков: 78 callback + 19 message,
  конфликтов маршрутизации среди новых префиксов нет;
- отчёты учителя, выгрузка CSV (61 колонка) и переключение ИИ — на тестовом классе.

## Что сознательно не делалось

- Таймеры на вопрос, отчёт по времени ответов и снятие подсказки с мини-контрольной —
  обсуждалось, отложено.
- Конфигурация Railway и Volume — по решению владельца не трогали. Напоминание:
  база — файл SQLite (`~/.rututor/bot.db`). Если к сервису не подключён Volume,
  она стирается при каждом деплое. Проверить путь и наполнение: `/dbstatus`.
