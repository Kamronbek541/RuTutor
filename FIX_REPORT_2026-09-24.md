# Отчет: потеря данных при деплое на Railway

Дата: 2026-09-24

## Что случилось

После деплоя пропали классы, ученики, XP и кеш уроков: `/admin` показывал
«Ученики: 0 | Учителя: 0».

## Причина

Бот хранит всё в одном файле SQLite. Путь по умолчанию был `~/.rututor/bot.db` —
это домашний каталог **внутри контейнера**. Файловая система контейнера Railway
временная: при каждом деплое она пересоздаётся из образа, и всё, что лежало вне
подключённого Volume, исчезает.

Прошлое исправление (`FIX_REPORT_2026-05-22_PERSISTENCE.md`) решало другую задачу —
чтобы база не терялась при распаковке новой версии рядом со старой на Windows.
Для контейнера этого недостаточно: там проблема не в смене папки, а в том, что
диск живёт только до следующего деплоя.

## Что сделано

### 1. Автоматическое определение подключённого диска

`storage._default_data_dir()` теперь ищет постоянный том в таком порядке:

1. `RUTUTOR_DATA_DIR` / `RUTUTOR_DB_PATH` — если путь задан вручную;
2. `RAILWAY_VOLUME_MOUNT_PATH` — Railway выставляет эту переменную, когда к сервису
   подключён Volume;
3. типовые точки монтирования `/data`, `/mnt/data`, `/var/data`, `/app/data` —
   если каталог существует и в него можно писать (проверяется реальной записью
   файла, а не только наличием каталога);
4. только если ничего не нашлось — прежний `~/.rututor`.

База ложится в `<том>/rututor/bot.db`. Подключение Volume не требует
изменений кода или переменных окружения — бот подхватывает его сам.

### 2. Бот сам сообщает, что данные в опасности

`storage.is_persistent_storage()` определяет, лежит ли база на постоянном диске.
Локальный запуск всегда считается безопасным; явно заданный путь считается
осознанным выбором владельца.

Если база на временном диске, при старте бот:

- печатает крупное предупреждение в логи Railway;
- присылает сообщение всем администраторам в Telegram.

`/dbstatus` теперь первой строкой показывает статус хранилища:
«✅ постоянное хранилище» либо «⛔️ ВРЕМЕННЫЙ диск!» с инструкцией.

### 3. Резервная копия одной командой

`/dbbackup` (только админ) присылает файл базы прямо в чат. Копия снимается
через `sqlite3.backup()`, а не обычным копированием файла — при включённом WAL
простое копирование даёт битую базу.

Восстановление: положить файл на сервер и указать путь в `RUTUTOR_LEGACY_DB_PATH` —
при старте бот перенесёт данные, если рабочая база ещё пустая.

### 4. Перенос старой базы при подключении тома

В список кандидатов на разовый перенос добавлен прежний путь `~/.rututor/bot.db`.
Если том подключить к работающему контейнеру, данные переедут сами.

### 5. Конфигурация деплоя в репозитории

Добавлены `railway.json` (builder NIXPACKS, `startCommand: python bot.py`,
перезапуск при падении) и `Procfile` (`worker: python bot.py`), чтобы команда
запуска не жила только в настройках дашборда. Инструкция — в `DEPLOY.md`.

## Что нужно сделать владельцу вручную

Код не может создать Volume — это делается в дашборде:

**Railway → сервис → Settings → Volumes → New Volume → Mount path `/data` → Deploy.**

После этого `/dbstatus` должен показать
`✅ постоянное хранилище` и путь `/data/rututor/bot.db`.

Потерянные данные восстановить нельзя: файла с ними не осталось. Классы нужно
создать заново, ученикам — заново зайти по коду `/join`. Уроки, написанные
вручную (`s1_01`–`s1_05`, `s2_07`–`s2_09`), доступны сразу; остальные
догенерируются при первом открытии или командой `/prewarm`.

## Изменённые файлы

Новые: `railway.json`, `Procfile`, `DEPLOY.md`, `tests/test_storage_location.py`.
Изменены: `storage.py`, `bot.py`, `admin.py`.

```bash
python3 -m unittest discover -s tests   # 45 тестов, OK (было 40)
python3 -m compileall -q .              # OK
```

Отдельно проверено:

- Railway без тома → `persistent=False`, предупреждение в логах и админам;
- Railway с `RAILWAY_VOLUME_MOUNT_PATH` → база в `<том>/rututor/bot.db`,
  `persistent=True`;
- явный `RUTUTOR_DATA_DIR` → используется он, лишних предупреждений нет;
- локальный запуск → как раньше, без предупреждений;
- `/dbbackup` → файл базы приходит в чат, данные в копии читаются.
